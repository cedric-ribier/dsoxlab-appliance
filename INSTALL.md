# Installation guide

*[Version française](INSTALL.fr.md)*

This is for **using** the appliance — downloading it, importing it, and
getting to your first lab. If you're looking to **build** it yourself
from source, see [`RELEASE.md`](RELEASE.md) instead.

> **This is a proof-of-concept release (v0.1.x).** It has been tested
> by the author and a small number of external testers on specific
> hardware/hypervisor combinations — not a broad compatibility matrix
> yet. See [`PLAN.md`](PLAN.md) for what's validated and what isn't.

## 1. Before you download anything — check your machine

| | Minimum | Comfortable |
| --- | --- | --- |
| CPU | 4 vCPU | 8 vCPU |
| RAM | 8 GB | 16 GB |
| Disk | 20 GB free | 40 GB free |

These are minimums for the `shell` labs. If you also want the `vm`
labs (KVM/Incus, installed automatically — see step 4), your host CPU
needs **nested virtualization** (Intel VT-x or AMD-V), and it must be
enabled — not just physically present.

**Check and enable nested virtualization now, before importing
anything** — this cannot be fixed after the appliance is already
running, only before its first boot:

- **VirtualBox**: in the VM's settings (VM powered off) →
  *System → Processor* → check *Enable Nested VT-x/AMD-V*.
- **VMware Fusion / Workstation**: in the VM's settings (VM powered
  off) → *Processors* → check *Enable hypervisor applications in this
  virtual machine*. **Not on by default** — importing and starting the
  VM without checking this first means the `vm` labs silently won't
  work (the appliance detects this safely and does nothing harmful,
  but you'll be missing functionality without knowing why).

If your CPU or hypervisor doesn't support nested virtualization at
all (common on older CPUs, some cloud-hosted dev environments, or
Apple Silicon), that's fine — the `shell` labs work regardless. The
`vm` labs won't.

## 2. Download

Get the `.ova` file and `SHA256SUMS` from the
[Releases page](https://github.com/stephrobert/dsoxlab/releases) (or
this repository's own Releases page, while this proposal isn't merged
yet).

Verify the download before importing anything:
```bash
sha256sum -c SHA256SUMS
```
(macOS: `shasum -a 256 -c SHA256SUMS` if `sha256sum` isn't installed.)

## 3. Import

### VirtualBox
Double-click the `.ova`, or *File → Import Appliance*.

**Before starting it**, check the network adapter setting — VirtualBox
pre-selects *some* host network interface by default on import (often
your Wi-Fi, not necessarily what you want), and it won't ask you to
confirm. In the VM's settings → *Network* → *Adapter 1*, confirm it's
attached to *Bridged Adapter* and pointing at the network interface
you actually want the appliance reachable on.

### VMware Fusion / Workstation
Double-click the `.ova`, or *File → Import*. Before first boot, also
set the nested virtualization option from step 1 if you want the `vm`
labs.

## 4. First boot

The first boot takes longer than later ones — it's doing real setup
work:
- Creates your login account.
- Adapts network configuration to your specific hypervisor.
- If nested virtualization is available and enabled: installs and
  configures KVM/libvirt and Incus (needs internet access).

Log in with:
```
login: user
password: MotDePasse
```
You'll be asked to set a new password immediately — this is expected,
not an error.

> **Keyboard layout note**: this appliance currently defaults to a
> French/AZERTY console layout. If your physical keyboard uses a
> different layout, typing `MotDePasse` at the login prompt may
> produce unexpected characters (some letters are in different
> positions between AZERTY and QWERTY, for example). If you get stuck,
> from any working terminal session try `sudo loadkeys us` (or your
> own layout's code) to switch temporarily, or watch for the exact
> characters your keyboard actually produces when following the
> on-screen prompt. This is a known limitation — see `PLAN.md`.

## 5. Set up your lab catalog

```bash
dsoxlab catalog list
dsoxlab catalog add <id>
```

Then check everything's in order:
```bash
dsoxlab doctor
```

## 6. Steps that aren't automatic yet

The following are documented and shown directly on-screen by `dsoxlab`
itself when you need them — they only come up starting from lab `L2`
in the Linux track, at which point you're expected to be comfortable
typing commands and following on-screen instructions (not really a
beginner anymore, by definition of having completed `L1`):

- **libvirt/KVM storage pool** — needs to be created before `vm` labs
  using that provider can run.
- **Incus network and storage pool** — same idea, for the Incus
  provider.
- **SSH key** — not generated by default; run
  `dsoxlab instructor bootstrap`.

This list isn't exhaustive and will grow as more of it gets documented
properly — if you hit a step that isn't listed here but should be,
that's useful feedback for this proposal.

## Troubleshooting

- **No network / DHCP doesn't come up**: confirm the network adapter
  setting from step 3 (VirtualBox) — this is the most common cause.
- **`vm` labs don't work, no error shown**: nested virtualization
  wasn't enabled before first boot (step 1). Enable it now, then
  reboot the VM — the appliance retries automatically on every boot
  until it succeeds once.
- **Can't type the login password correctly**: see the keyboard note
  in step 4.
- **Anything else**: check `PLAN.md` for what's already known not to
  work yet, then open an issue.
